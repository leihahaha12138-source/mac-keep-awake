## 为什么需要它

macOS 上「睡过去」有两条**完全独立**的路径。几乎所有保活工具让人困惑，根源都在这里：它们只挡住了其中一条，而用户以为两条都挡住了。

| 触发路径 | 机制 | 谁能挡住 |
| --- | --- | --- |
| **空闲计时器**：一段时间没人碰键鼠 | 用户态电源断言（IOPMAssertion） | `caffeinate`、Amphetamine、KeepingYouAwake、Lungo、Caffeine……一切断言类工具 |
| **合盖**：关上屏幕 | **霍尔传感器的硬件中断** → clamshell sleep | **只有 `sudo pmset -a disablesleep 1`**。断言类工具在架构上就够不着 |
| **显示器全部断开** | 零显示器 → 强制睡眠 | 同上 |

第一行和第二行的区别，就是全部问题所在。断言是在用户态**请求**系统别睡，系统认这个请求；而合盖是一次硬件中断，走的是另一条路，根本不看断言。

**那些「合盖还能跑」的工具是怎么做到的？**

它们不是在**挡**合盖，而是在**绕**合盖：靠外接显示器进入 clamshell 模式「骗」过系统，而 clamshell 模式本身要求外接屏必须亮着。所以那种「合盖可用」的体验，代价是你得一直挂着一块屏。

本项目是**直接挡**：合盖 + 熄屏 + 继续跑。代价是必须用 `disablesleep` 这个开关——它是全局的、持久的、且系统不会有任何提示，所以下面花了很大篇幅讲怎么把它关起来。

典型适用场景：合盖丢在桌上跑通宵编译、挂着几十 G 的下载、维持一条长 SSH 或远程桌面连接、跑本地服务等外部访问。

## 合盖熄屏：本项目补的那一刀

`disablesleep` 挡住的是**整个 clamshell 流程**，连「关掉内建屏」这一步也一起挡掉了。结果就是：合盖了，但屏幕还亮着——在包里暗暗发光、持续耗电、持续发热。

本项目补上了这一步。四个条件同时成立才动手：

```text
开关开着  &&  已合盖  &&  在线显示器列表里没有外接屏  &&  内建屏还亮着
                              ↓
                 /usr/bin/pmset displaysleepnow
```

**有外接屏时刻意不动作**——那时你正在用 clamshell 模式，外接屏就是工作屏，把它灭掉是事故。

判定逻辑被写成一个纯函数，`--check` 会用合成数据把整张真值表跑一遍（见 [工作原理](#工作原理)）。

### 关于锁屏

熄屏之后系统可能要求输入密码。这是 macOS 自己的策略（取决于「系统设置 → 锁定屏幕」里「需要密码」设的是「立即」还是延时），**与本工具无关，也不影响后台继续运行**。锁屏是一层 UI，你的下载、编译、SSH 会话都在继续。

## 功能特性

### 菜单栏图标三态

| 图标 | 含义 |
| --- | --- |
| 实心月亮 | 已开启 |
| 空心月亮 | 已关闭 |
| 感叹号 | **风险性**自动松开（电池到下限、系统进入低电量模式） |

计时器到点、开盖这类**预期之内**的松开不报警——它们是你自己设的，不是出事了。

### 状态可视化

菜单里常驻显示当前电源状况，不用去开系统设置对照：

```text
电源：适配器供电 · 电量 87%
盖子：已合上 · 在线显示器 1 台（含外接屏）
内建屏：已熄灭
```

合盖且零显示器时，会额外提示一句「系统可能因显示器丢失而睡眠」——菜单里的提示原文就是这个。此时你手上没有任何屏幕可以确认状态，只能靠 SSH 之类的方式看机器是否还活着。

### 安全阀

一个「忘了关」保护网。默认值就已经能兜住最常见的翻车方式——合盖塞进包里，电一路跑到底。

| 安全阀 | 默认 | 说明 |
| --- | --- | --- |
| 电池低于阈值自动松开 | **开**，20% | 仅在电池供电时判定；阈值可选 10 / 15 / 20 / 30 / 50% |
| 低电量模式时自动松开 | **开** | 只在开启保活**之后**系统才进低电量模式时触发 |
| 计时器到点自动松开 | 关 | 不限 / 30 分 / 1 时 / 2 时 / 4 时 |
| 盖子打开后自动松开 | 关 | 默认关，否则开盖看个消息就把保活关掉了 |

「低电量模式时自动松开」有一个刻意的细节：它比较的是**开启保活那一刻**的低电量模式状态。如果你按下开关时系统已经是低电量模式（比如你主动开的），它不会立刻松开——否则这个开关根本没法用。

「盖子打开后自动松开」默认关，理由同上：合盖出去、回来掀一条缝看消息，恰恰是你最需要它继续跑的时候。

### 其它

- 保活期间每 5 秒巡检一次系统状态，打开菜单时也会立即刷新。
- 退出时自动复位 `disablesleep`（见 [安全设计](#安全设计)）。
- 纯菜单栏 App，不占 Dock、没有主窗口，设置里找不到它。

## 不做什么与已知边界

这一节比功能列表更重要。诚实地划清边界：

- **没有做代码签名，也没有公证（notarization）**。构建脚本只做 ad-hoc 签名。自己构建的产物在本地运行，一般不会触发 Gatekeeper；如果系统提示「无法验证开发者」或「已损坏」，在「系统设置 → 隐私与安全性」里放行即可。
- **只支持 Apple Silicon**。构建目标是 `arm64-apple-macos13.0`，Intel Mac 不适用。
- **无风扇机型合盖跑重载会热降频**。合盖之后散热更差，这是物理问题，软件挡不住。要长时间跑满负载，把机器立起来、放在通风处，或者干脆别合盖。
- **`disablesleep` 是未文档化的隐藏开关**。Apple 从未承诺它的存在与行为，未来的 macOS 版本可能改变或移除它。
- **只管「不让它睡」，不管「把它叫醒」**。不做网络唤醒、不做定时开机。
- **不修改其它电源设置**。只动 `disablesleep` 这一个开关，不碰 `sleep`、`displaysleep` 等。
- **不拦锁屏**，也不做任何绕开锁屏的事（见上文）。
- **没有 CI、没有自动化测试流水线**。唯一的自检是 `--check`，它验证的是解析逻辑和判定逻辑，不是系统行为。

## 安装

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | macOS 13.0 或更高 |
| 芯片 | Apple Silicon（M 系列） |
| 编译环境 | **只需要 Command Line Tools**：`xcode-select --install`；**不需要安装 Xcode** |
| 编译器 | 系统自带的 `/usr/bin/swiftc` |
| 依赖 | 无第三方依赖，单文件 Swift + AppKit |

### 路径一：克隆后两条命令

```bash
git clone https://github.com/leihahaha12138-source/mac-keep-awake.git
cd mac-keep-awake

./build.sh      # 编译，产物在 build/不许睡.app
./install.sh    # 复制到 /Applications，并按需写入免密白名单
```

然后从「应用程序」或 Spotlight 打开「不许睡」，菜单栏会出现一个月亮图标。

### 路径二：手动构建

如果不想用脚本，或者想看清楚每一步：

```bash
# 1. 准备 App 目录结构
mkdir -p "build/不许睡.app/Contents/MacOS" "build/不许睡.app/Contents/Resources"

# 2. 编译
/usr/bin/swiftc -O -target arm64-apple-macos13.0 \
  -o "build/不许睡.app/Contents/MacOS/KeepAwake" \
  src/main.swift -framework AppKit

# 3. 放入 Info.plist（LSUIElement = true，即纯菜单栏 App）
cp Info.plist "build/不许睡.app/Contents/Info.plist"

# 4. 可选：ad-hoc 签名
/usr/bin/codesign --force --sign - "build/不许睡.app"

# 5. 安装到 /Applications
cp -R "build/不许睡.app" /Applications/
```

注意：手动安装这一步没有写入 sudoers 白名单。第一次点菜单里的总开关会弹出一个「没有拿到免密授权」的提示，点一下 `./install.sh` 补齐即可。

### install.sh 具体做了什么

1. **先探测**：用 `sudo -n -l /usr/bin/pmset -a disablesleep 1` 问系统「这条路现在通不通」。如果**已经有**覆盖这两条命令的免密白名单（比如别的保活工具留下的），直接跳过，**什么都不写**。
2. **只写两条命令**。没有现成白名单时，写入 `/etc/sudoers.d/keepawake`，内容是一条规则、两条命令，并限定到运行安装脚本时的当前用户：

   ```text
   # 不许睡 — 仅允许以下两条命令免密执行；其它 pmset 操作仍需管理员密码
   <当前用户名> ALL=(root) NOPASSWD: /usr/bin/pmset -a disablesleep 1, /usr/bin/pmset -a disablesleep 0
   ```

3. **先校验，后生效**。新规则先写成 `keepawake.draft`——带点的文件名会被 sudo 的 `includedir` 直接忽略，所以这个阶段写坏了也影响不到系统。接着用 `visudo -cf` 校验语法，**通过才 `mv` 成正式文件名**；校验失败就把草稿删掉、退出，系统文件原封不动。
4. **写完自检**：再确认一次免密真的可用，不可用就报错退出。
5. 最后把 `build/不许睡.app` 复制到 `/Applications`。

## 使用说明

打开菜单，从上到下依次是：

```text
不许睡
状态：已开启 —— 合盖 / 显示器关闭都继续运行
✓ 不许睡（合盖 / 显示器关闭都继续运行）
✓ 合盖后熄灭内建屏幕
─────────────────────────────────
安全阀（满足条件时自动松开）
✓ 电池低于 20% 自动松开              ▸
  计时器：不限                       ▸
✓ 低电量模式时自动松开
  盖子打开后自动松开
─────────────────────────────────
电源：适配器供电 · 电量 87%
盖子：已合上 · 在线显示器 1 台（含外接屏）
内建屏：已熄灭
─────────────────────────────────
退出
```

> 上面是各项目的**默认状态**（`✓` 表示勾选）。第一项「状态」行在未开启时显示为「状态：正常，系统按原设置睡眠」。

| 菜单项 | 说明 |
| --- | --- |
| **不许睡** | 总开关。勾上后执行 `sudo pmset -a disablesleep 1`，从此合盖、显示器全灭都不再触发睡眠；再点一次即松开 |
| **合盖后熄灭内建屏幕** | 上文那「一刀」。默认开。有外接屏在线时不会动作 |
| **电池低于 N% 自动松开** | 默认开、阈值 20%。可选 10 / 15 / 20 / 30 / 50%。**只在电池供电时判定**，插着电不会因为电量数字触发 |
| **计时器** | 默认「不限」。可选 30 分钟 / 1 小时 / 2 小时 / 4 小时。到点自动松开，属于预期内松开，不报警；开启状态下标题会显示剩余分钟数 |
| **低电量模式时自动松开** | 默认开。只在开启保活之后系统才进入低电量模式时触发 |
| **盖子打开后自动松开** | 默认关。理由见上文 |
| **状态行** | 电源 / 电量 / 盖子 / 在线显示器台数 / 内建屏状态，常驻显示 |
| **退出 / 松开并退出** | 未开启时是「退出」，开启时是「松开并退出」——**始终用这一项退出** |

关于退出：它是一个纯菜单栏 App，没有 ⌘Q 可按。**请用菜单里的「退出」项**，它会先把 `disablesleep` 复位再终止进程。如果强杀进程（活动监视器、`kill -9`），标志会残留在 `1`——机器不听你的话也不睡，直到下次启动 App 时被自动复位，或者跑一次 `uninstall.sh`。

授权丢失时（比如从没跑过 `install.sh`），点击总开关会弹出一个警告框，提示你在项目目录里运行一次 `./install.sh`，并附上系统的原始报错。

## 安全设计

`disablesleep` 是**全局、持久、系统毫无提示**的开关。忘了关、合盖塞进包里，电会一路跑到底，还可能闷出高温。所以这个工具从设计上就把它当成危险品处理：

1. **白名单只放两条命令。** `/etc/sudoers.d/keepawake` 里只有一条规则、两条命令（`disablesleep 1` 和 `disablesleep 0`），并限定到安装时的当前用户。其它 `pmset` 操作——改 `sleep`、改 `displaysleep`、关机等等——**仍然需要管理员密码**。

2. **先探测，再写入。** 安装脚本不问「该不该写」，而是问系统「这条路现在通不通」。已经有别的工具留下的白名单覆盖了这两条命令，就什么都不写，绝不重复添加、绝不覆盖别人的文件。

3. **先校验，后生效，失败自动回滚。** 新规则先落成一个被 `includedir` 忽略的 `.draft` 文件，`visudo -cf` 语法校验通过才改名生效；校验失败就删掉草稿并退出，系统不被改动。

4. **退出即复位。** 菜单里的「退出 / 松开并退出」会先复位 `disablesleep`。App 启动时如果发现系统里残留着 `SleepDisabled = 1`（上次异常退出留下的），**只复位，绝不自动开启**——启动时的保活状态永远是「关」。

5. **安全阀默认就开着两条。** 电池下限和低电量模式这两条默认启用，正是为了兜住「忘了关」（见 [功能特性](#功能特性)）。

6. **被改回时会停手并报警。** 保活期间每 5 秒比对一次系统里的 `SleepDisabled`。如果发现它被系统或别的程序改了回去，App 会真的关掉这个标志、停止保活，并把图标切成感叹号——而不是留在界面上假装自己还在工作。

7. **读不到状态就不判断。** `pmset -g` 解析失败时，所有自动判断暂停，菜单里显示「警告：读不到系统电源设置，自动判断已暂停」，避免把一次偶发的读取失败误当成状态变化而胡乱熄屏或松开。

## 工作原理

### 1. 挡睡眠：一个 `pmset` 开关

```bash
sudo pmset -a disablesleep 1    # 挡：合盖、显示器全灭都不再进入睡眠
sudo pmset -a disablesleep 0    # 松开：交回 macOS 默认行为
```

`disablesleep` 是 `pmset` 的一个未文档化参数，在 `pmset -g` 的输出里显示为 `SleepDisabled`。它不是 IOPMAssertion 断言，而是直接改电源管理的行为，所以能挡住断言类工具在架构上够不着的合盖路径。程序内部用 `sudo -n`（非交互）执行这两条命令，拿不到权限时不会弹系统密码框，而是直接失败并给出提示。

### 2. 读状态：三个来源

| 想知道什么 | 怎么读 |
| --- | --- |
| 保活标志是否生效、是否处于低电量模式、是否插着电、电量多少 | `pmset -g` 与 `pmset -g batt` |
| 盖子是否合上 | `ioreg -r -k AppleClamshellState -d 4`，看有没有 `AppleClamshellState = Yes` |
| 有几台显示器在线、哪台是内建、哪台已经睡了 | `CGGetOnlineDisplayList` + `CGDisplayIsBuiltin` + `CGDisplayIsAsleep` |

`pmset -g` 的输出有两种排版——制表符分隔的（`SleepDisabled<TAB><TAB>1`）和空格对齐的（`lowpowermode         0`）——所以解析时按**任意空白**切分，而不是按固定列宽。Cocoa 侧判断「插着电」靠匹配 `'AC Power'`，电量靠抓第一个 `N%`。

### 3. 合盖熄屏：一个判定

```text
开关开着  &&  已合盖  &&  无外接屏在线  &&  内建屏还在亮
```

`CGDisplayIsAsleep` 是关键的一环：**休眠中的显示器仍然留在在线列表里**，所以不能靠「在不在列表里」判断亮没亮，必须专门问它睡没睡。同理，「有没有外接屏」看的是在线列表里除内建屏之外的部分——这就是区分「你在用 clamshell 模式」和「机器在包里」的依据。

判定结果是 `true` 时，调 `/usr/bin/pmset displaysleepnow` 把内建屏灭掉。

### 4. 自检

只读、不修改系统：

```bash
./build/不许睡.app/Contents/MacOS/KeepAwake --check
```

它跑两组回归——`pmset -g` 解析的四种排版、以及合盖熄屏判定的整张真值表（合盖 / 开盖 × 有 / 无外接屏 × 屏亮 / 屏灭 × 选项开 / 关）——再打印一次实时状态。输出形如（数值随机器状态变化）：

```text
解析自检: PASS
实时状态: SleepDisabled=0 lowPowerMode=0 onAC=1 battery=100 lidClosed=0 displays=1 external=0 builtinAwake=1 ok=1
熄屏判定自检: PASS
```

## 卸载

```bash
./uninstall.sh
```

三步：

1. 松开保活标志（`sudo pmset -a disablesleep 0`）并回显当前值；
2. 删除 `/Applications/不许睡.app`；
3. 删除本项目写入的 `/etc/sudoers.d/keepawake`。

**不会碰别人的 sudoers 文件。** 如果系统里还留着别的保活工具的白名单（脚本会检查 Amphetamine 的那一份），它会提示你一句，但不会动它。

也可以手动来：

```bash
sudo pmset -a disablesleep 0
rm -rf "/Applications/不许睡.app"
sudo rm -f /etc/sudoers.d/keepawake
```

## 常见问题

**Q：合盖之后屏幕怎么还亮着？**

A：因为「挡合盖」这个动作会连「关掉内建屏」一起挡掉。手工执行 `sudo pmset -a disablesleep 1` 然后合盖，屏幕就是亮着的——`disablesleep` 本身不带熄屏。只设了这个开关、没补这一步的工具都会这样。

本项目的「合盖后熄灭内建屏幕」专门补了这一刀，但它是菜单里的一项，可以被关掉。检查它有没有勾上；另外，如果你外接着显示器，程序会**刻意不熄屏**——那是 clamshell 模式，外接屏是工作屏。

**Q：合盖熄屏之后要输密码，正常吗？**

A：正常，而且与本工具无关。唤醒后要密码是 macOS 自己的策略，取决于「系统设置 → 锁定屏幕」里「需要密码」设的是「立即」还是延时。锁屏只是一层 UI，不影响后台运行——下载、编译、SSH 会话都照常继续。

**Q：开关明明关了，为什么它还是不睡？**

A：这个开关只控制「我们这一层」。真不睡，还有别的可能：

- 插着电时系统本来就可能不睡（某些机型在适配器供电下 `sleep` 就是 0，即永不自动睡眠）；
- 别的 App 还挂着 `NoIdleSleepAssertion` 之类的断言，比如播放器、下载器、会议软件；
- 系统里还残留着 `SleepDisabled = 1`（上次没干净退出，或者别的工具设了没松）。

查一下就知道：

```bash
pmset -g              # 看 SleepDisabled 是 0 还是 1
pmset -g assertions   # 看现在是谁在挂着断言
```

**Q：合盖熄屏会不会烧屏？**

A：不会。内建屏是 IPS LCD，不存在 OLED 那种永久烧屏问题。而且这一步做的恰恰是**把它灭掉**——比「合盖了屏幕还亮着」更省电、更凉快。

**Q：我怎么判断机器真的没睡？**

A：从另一台机器 SSH 进来看看，或者事后翻电源日志：

```bash
pmset -g log | grep "Entering Sleep"
```

没有新的 `Entering Sleep` 记录，就是没睡。

**Q：为什么菜单栏以外的任何地方都找不到它？**

A：`Info.plist` 里 `LSUIElement = true`，这是一个纯菜单栏 App（accessory app）——没有 Dock 图标、没有主窗口、不在「系统设置」的 App 列表里。一切操作都在菜单栏图标上。

**Q：需要装 Xcode 吗？**

A：不需要。`xcode-select --install` 装好 Command Line Tools 就有 `swiftc` 了。整个项目就是一个 Swift 单文件加一个 `Info.plist`。

**Q：为什么第一次安装要 sudo，还要写 sudoers？**

A：因为 `pmset -a disablesleep` 需要 root 权限。写白名单是为了让你之后点菜单就能开关，而不是每次都弹密码框。白名单只放两条命令，其它 `pmset` 操作照样要密码。详见 [安全设计](#安全设计)。

**Q：为什么第一次点开关弹了「没有拿到免密授权」？**

A：说明 `install.sh` 那一步没做过（手动安装的话就不会做）。到项目目录跑一次 `./install.sh` 即可。
